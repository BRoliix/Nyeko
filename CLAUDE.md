# Nyeko — guide for AI coding agents

Nyeko (formerly Kestrel) is Broly's customised copy of Coucou (github.com/Louis-CFM/coucou, MIT; remote `upstream`, push disabled). Internal names (NotchBuddy, CoucouKit, Mochi) are kept so upstream fixes still merge. The Coucou name, Mochi, Coucou's icon and sounds are © Louis Raillé (LICENSE-ASSETS.md) and are in no Nyeko build: Nyeko has its own name, Nyo (a tabby cat drawn in code wherever Mochi was: `CoucouKit/NyoPainter.swift`, `windows/src/mochi/nyo.ts`, Android `nyeko/NyoFace.kt`, all from the same design numbers; island, greeting, file drop, widgets), its own icons (`scripts/nyeko-icons.py` writes every platform's) and its own sounds (`scripts/nyeko-sounds.py` writes the 29 WAVs for Mac/Windows and the 14 Android ones; re-run it rather than editing WAVs). User-visible text says Nyeko/Nyo in every language; only the credits name Coucou. Names a user can see on disk or in a link are Nyeko's too: the Mac's data and relay live in `~/Library/Application Support/Nyeko` (copied once from `NotchBuddy`) as `nyeko-hook`/`nyeko-hook.py` with `nyeko.sock`; Windows/Linux run `Nyeko.exe` and `nyeko-hook(.exe)` (the old `coucou-hook` is kept current while hooks written before still call it); agent plugins are `nyeko.json`/`nyeko.js`/`nyeko.ts`/`plugins/nyeko` and the Antigravity group `nyeko` (the Coucou-named ones are recognised, replaced and removed); pairing links are `nyeko://pair` (phones still accept `coucou://`). Source-level names (NotchBuddy, CoucouKit, Mochi types, the `coucou_*` payload keys, the relay's `coucou.v1` protocol strings, pill IDs) stay for upstream merges. `README.md` is Nyeko's. Two repos: **BRoliix/Nyeko** is public (code under MIT, Nyo/name/icons/sounds all rights reserved: `LICENSE-ASSETS.md`), with releases and free CI; **BRoliix/Kestrel** is the private working copy with Coucou's history and the `upstream` remote. Publish Kestrel's `main` to Nyeko as a snapshot (`scripts/nyeko-publish.sh`), never Kestrel's history. Coucou's media, site, design files, changelog and Linux/Homebrew/Nix packaging are not in Nyeko; when an upstream merge brings them back, delete them again.

Nyeko differs from Coucou: the mascot is Nyo, a cat, in the Sticker Pop style (cream #FFF6E9, ink #2B1D12, tangerine #FF7A2F, mint #2EC4B6, bubblegum #FF8FB1; Fredoka headings, Nunito text; chunky ink outlines) — the redesign is under way; no crypto ticker or portfolio; the self-updater is off (`MacUpdate.enabled = false`), Nyeko is updated from its own repo; app name Nyeko, bundle ID `com.broliix.nyeko`; the phone side is a web app (`phone/web`, Cloudflare Pages) instead of the native iPhone app: it talks protocol v1 end-to-end encrypted through the user's own link relay (`android/relay`, which also accepts the access key as a `coucou.access.` sub-protocol for browsers); the Mac side is `Sources/App/PhoneWeb/` (relay client in the `pc` role, the Android link's hub for decisions, Nyeko's `mac`/`control`/`ask` messages, content-free Web Push signed with a VAPID key). Setup: `phone/README.md`; the relay (`relay/` upstream, Broly's own copy deployed as broly-relay.broliix.workers.dev) requires a shared secret. Nyeko is becoming a Mac controller: the island opens on a Mac home (`IslandView.mac`, `MacHome.swift`, `MacHomeView.swift`: now playing, next Calendar event, Notetaker, quick-launch apps, quick actions) whenever no coding session is running; the agents' overview stays one tab away. The window opens on a Home page (`FlowHubMacHome.swift`). Any app's Now Playing is read through /usr/bin/osascript + MediaRemote (`SystemNowPlaying.swift`, only while shown) and driven with media keys; notifications come from WhatsApp, Mail, Calendar and, opt-in with Full Disk Access, the Notification Center database (`NotificationFeed.swift`); typed messages to Nyo run Mac commands first (`NyoActions.swift`), else go to Claude. Every live coding session is listed one by one (`SessionList.swift`: `PillSessionRegistry.list()` → `AppState.liveSessions`), in the island's `.sessions` tab (default with 2+ sessions), the window's Home and on the phone; tapping a session brings its editor window or terminal forward, or opens its pending request. On the phone, tapping a session opens its conversation (`SessionTranscript.swift`, read from the Claude Code transcript while open) and lets you message it (`SessionChat.swift`): while Claude works the message waits and the Stop hook hands it over (`coucou_kind: stop_check` → `{"decision":"block"}`); when Claude is idle Nyeko types it in (Terminal/iTerm tab found by tty or session id, other apps brought forward), never while the Mac is locked. The phone can also start a new session (`launch` → `SessionLauncher.launch`, only in the launcher's recent folders, sent by id in the `mac` status) and opens it once its first hook event arrives (`started`). The native Android app (`android/`, upstream's Coucou for Android) is Nyeko too: applicationId `com.broliix.nyeko.android`, Nyo drawn in code where Mochi was (`ui/NyoFace.kt`, `MochiView`, the Widgets), a floating Nyo over other apps (`ui/FloatingNyo.kt`) beside the camera-hole island, the `nyeko` capability (`core/NyekoData.kt`, `app/NyekoModel.kt`, `ui/NyekoScreens.kt`), and relay-only `coucou://pair` links: the Mac pairs it in a second relay room (`NyekoPhoneKind.android`). Everything is on `main` (no other branches). Releases: only the manual **Release Nyeko** workflow (`.github/workflows/nyeko-release.yml`) publishes, one GitHub Release `nyeko-1.0.<build>` with Nyeko.dmg, Nyeko-Windows-setup.exe and Nyeko.apk (+ their `nyeko-*.json`); `Build`, `Windows` and `android` only test; the download page (`phone/web/_worker.js`) serves the newest release holding each file. One phone holds several computers (the web app's computer list; the Android app's first pairing plus `link/ExtraComputers.kt`, ids tagged per computer by `core/ComputerTag.kt`); each computer and OS account has its own id and name (`PhoneWeb/NyekoIdentity.swift`, Windows `pairing::computer_id`/`phone_name`, `cid` in pairing codes, welcome and `mac` status), and phones match a re-paired computer by room or `cid`, never by name. Nyeko on Windows/Linux is `windows/src-tauri/src/phone_link/nyeko.rs` (the same `nyeko` messages: status, system controls, a session's conversation and messages, new sessions, all apps), coucou-hook's Stop `stop_check`, and a second relay room for the web app (one QR for both phones).

Coucou is a native macOS app (`NotchBuddy/`); `windows/` is the Tauri version for Windows and Linux. Mochi, a small animated character living in the MacBook notch, shows AI coding agent sessions (Claude Code, Gemini CLI, Antigravity and more) and a few integrations, and lets the user approve, answer, chat and drop files from the notch.

## Where things are
- `NotchBuddy/Sources/App/` — Mac-only Swift code. `NotchBuddy/Sources/CoucouKit/` — code shared with the iPhone app (Mochi's BotEngine and outfits, pills, diff, models). `NotchBuddy/Sources/Phone/` — iPhone app (`CoucouPhone` target), with its widgets in `Sources/Widgets/` and the expanded approval notification in `Sources/NotificationContent/`. `NotchBuddy/Resources/sounds/` — the 28 WAV sounds. `NotchBuddy/project.yml` — XcodeGen project (never edit the `.xcodeproj` by hand).
- `NotchBuddy/Sources/CoucouKit/PillCatalog.swift` — single source of truth for all declared pills (workspace tools, agents, AI providers, services). Every pill ID, color, category and subtitle lives here.
- `docs/SPEC.md`, `docs/INTEGRATIONS.md` — behaviour, views, states, integrations (in French).
- `windows/` — the Tauri app for Windows and Linux: Rust in `src-tauri/`, TypeScript in `src/`, the `coucou-hook` relay in `hook/`. `windows/README.md` lists what differs from the Mac.
- `relay/` — the Coucou relay, a stateless Cloudflare Worker that forwards the iPhone Live Activity pushes (it holds the APNs key, which must never ship in an app). See `relay/README.md`.

## Build
Nyeko, every day: `./scripts/nyeko-install.sh` (scheme `Nyeko`, config `DebugLocal`, signed with Broly's own Apple Development certificate, installed as /Applications/Nyeko.app).

Upstream's own builds:
```
cd NotchBuddy && xcodegen && xcodebuild -scheme NotchBuddy -configuration Debug build
```
To run upstream day to day on the Mac (signed, iPhone link, permissions kept across builds): `./scripts/dev-install.sh` — it installs the only Coucou in /Applications and removes the copies earlier builds left.
Windows and Linux: `cd windows && npm install && npm run tauri dev`

## Rules
- Swift 6, SwiftUI + AppKit. No third-party dependencies unless truly unavoidable. The character is drawn in code (`Canvas` + `TimelineView`), no Rive/Lottie/images.
- Secrets live in the Keychain, never on disk or in git.
- No telemetry. Network calls only to services the user configured.
- Never block Claude Code: if the app doesn't answer, the hook exits immediately.
- Never overwrite `~/.claude/settings.json`: dated backup, merge, show the diff, write only after the user confirms.
- Never send an email or approve a Claude Code or Codex permission without an explicit click.
- Performance: 0 % CPU when the island is hidden.
- Keep the bundle identifier `com.broliix.nyeko` (Keychain items, preferences and permissions depend on it). Never sign with the original author's team (256AUJ9555).
- Never restyle what already ships (pills, cards, Settings, chat…): existing views stay exactly as they are in `main`, which is the App Store build. Change the look of an existing view only when explicitly asked.
- Pill IDs are stable contract values (Keychain, UserDefaults, hook routing): never rename an existing pill ID.
- New views follow the existing app style.
- CI workflows are manual-only (`workflow_dispatch`). Run them on the public BRoliix/Nyeko, where GitHub-hosted runners are free; the private Kestrel has a paid minute allowance.
- Upstream's release rules below apply to Coucou releases, not to Nyeko builds.
- Every release adds its CHANGELOG.md section, a row in the README Versions table, and commits the regenerated Info.plist with the new version.
- Every release also adds its What's new, shown once in the notch or the island after Coucou updates itself: an entry for the new version in `NotchBuddy/Resources/whats-new.json` (Mac, the 16 languages) or `windows/src/whats-new/whats-new.json` (Windows and Linux, the 14 languages). 1 to 4 items picked from the CHANGELOG section, each with an icon from `scripts/test-whats-new.py`, a short title and one line, translated in every language. `python3 scripts/test-whats-new.py` checks it; CI and `release.sh` fail without it.
